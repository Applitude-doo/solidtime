# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

solidtime — open-source time tracker (AGPL-3.0). Laravel 13 / PHP 8.3 backend with PostgreSQL, Vue 3 + TypeScript frontend served via Inertia, Filament admin panel, Passport for API auth, Fortify for web auth. Local dev runs through Laravel Sail (`docker-compose.yml`: app, `pgsql`, `pgsql_test`) behind a Traefik reverse proxy at `solidtime.test` / `vite.solidtime.test`.

## Commands

Backend (run inside Sail with `./vendor/bin/sail ...` if not running PHP locally):

```bash
composer test                 # php artisan test --stop-on-failure
composer ptest                # parallel
php artisan test --filter=TagEndpointTest            # single class
php artisan test --filter=test_index_endpoint_fails_if_user_has_no_permission_to_view_tags  # single method
php artisan test tests/Unit/Endpoint/Api/V1/TagEndpointTest.php
composer analyse              # PHPStan level 7 (phpstan.neon)
composer fix                  # Laravel Pint formatting
composer generate-typescript  # regenerate resources/js/types/models.ts from models
composer refresh-schema-dump  # after migrations, dump schema from pgsql_test
```

Tests use the `pgsql_test` connection (see `phpunit.xml`), so the test Postgres container must be up.

Frontend:

```bash
npm run dev            # vite dev server
npm run build
npm run lint / lint:fix
npm run format / format:check   # prettier
npm run type-check     # vue-tsc
npm run test:unit      # vitest (e.g. npx vitest run resources/js/utils/useCurrentTimeEntry.test.ts)
npm run test:e2e       # Playwright, specs in e2e/; base URL from PLAYWRIGHT_BASE_URL (default http://solidtime.test)
npx playwright test e2e/tags.spec.ts
npm run zod:generate   # regenerate API client from running app's /docs/api.json
npm run build:packages # build @solidtime/api and @solidtime/ui workspaces
```

Before committing (per CONTRIBUTING.md): backend → `composer fix && composer analyse`; frontend → `npm run lint:fix && npm run format`.

## Architecture

### Multi-tenancy and permissions
Almost everything is scoped to an `Organization`. A `User` belongs to organizations through `Member` (which carries the `role`). API routes are nested under `/api/v1/organizations/{organization}/...`.

Authorization is **not** done with Laravel policies. `App\Service\PermissionStore` maps roles (owner, admin, manager, employee, placeholder) to string permissions like `tags:view`, `time-entries:update:own`, `projects:view:all`. API controllers extend `App\Http\Controllers\Api\V1\Controller` and call `checkPermission($organization, 'perm')` / `checkAnyPermission` at the top of each action. Controllers typically override `checkPermission` to also verify that the bound child model (`$tag`, `$project`, …) belongs to `$organization` — keep doing this for new resources. The `:own` vs `:all` suffix governs whether a member can act only on their own records.

### API layer (`app/Http/{Controllers,Requests,Resources}/V1`)
Pattern per entity: `XController` + `Requests/V1/X/{XIndexRequest,XStoreRequest,XUpdateRequest}` + `Resources/V1/X/{XResource,XCollection}`. OpenAPI docs are generated by Scramble from controller docblocks — the `@operationId` annotation becomes the method name on the frontend Zodios client (e.g. `api.getTags`, `api.createTag`), so changing it is a breaking frontend change. After API changes, regenerate `openapi.json`/the zod client (`npm run zod:generate`). Domain errors are thrown as subclasses in `app/Exceptions/Api` (e.g. `EntityStillInUseApiException`).

Business logic lives in `app/Service` (e.g. `TimeEntryService`, `BillableRateService`, `DeletionService`, `TimeEntryAggregationService`, `ReportService`); importers/exporters live in `app/Service/Import` and `app/Service/Export`. `BillingContract` is an interface the Billing extension implements; check `canAccessPremiumFeatures` rather than assuming billing exists.

### Web / frontend
`routes/web.php` mostly just returns `Inertia::render('PageName')`; pages in `resources/js/Pages` load their data client-side from the REST API, not via Inertia props. The frontend data layer is in `resources/js/utils`:
- `useXQuery.ts` — TanStack Vue Query hooks (query key `['x', organizationId]`, using `fetchAllPages` over paginated endpoints).
- `useX.ts` — Pinia stores holding mutations, which call `api.*`, wrap with `handleApiRequestNotifications`, then `queryClient.invalidateQueries`.

npm workspaces under `resources/js/packages`:
- `api` (`@solidtime/api`) — generated Zodios client (`openapi.json.client.ts`, do not hand-edit) plus exported types derived from operation aliases in `index.ts`.
- `ui` (`@solidtime/ui`) — shared Vue components, published to npm and reused by other solidtime clients; keep it free of app-specific imports (Inertia, app stores).

Routes are exposed to JS via Ziggy (`resources/js/ziggy.js`).

### Extensions (modules)
`extensions/` holds nwidart/laravel-modules extensions (Billing, Invoicing, Services, Auditing) pulled from separate repos at versions pinned in `extensions/manifest.json`; they're gitignored and may be absent locally. They're activated via `modules_statuses.json`, contribute Vite inputs/plugins through `vite-module-loader.js`, register Filament resources, and have their tests in the `Modules` PHPUnit suite. Core code communicates with them through events in `app/Events` (e.g. `BeforeOrganizationDeletion`, `MemberAdded`) and contracts like `BillingContract` — don't hard-depend on an extension from core.

### Tests
PHPUnit tests live mostly in `tests/Unit` (API endpoint tests under `tests/Unit/Endpoint/Api/V1`). Extend `Tests\TestCaseWithDatabase` (API endpoint tests extend `ApiEndpointTestAbstract`) and use `createUserWithPermission([...])` / `createUserWithRole(Role::X)` to set up a user+organization+member; then `Passport::actingAs($data->user)`. `assertQueryCount` + `enableQueryLog` are available for N+1 checks.

## Contribution notes
PRs from non-vouched authors changing >50 lines (excluding tests/lockfiles) are auto-closed; feature work needs an approved issue/discussion first. Follow existing naming conventions.
